# Multus performance reporting

Adapted from [ovn-kubernetes `contrib/perf`](https://github.com/ovn-kubernetes/ovn-kubernetes/tree/master/contrib/perf).

```
e2e/perf
├── generate_perf_report.py   # Build markdown + JSON from kube-burner metrics
├── compare-reports.py        # Compare PR run vs baseline JSON
├── download-artifacts.py     # Download GitHub Actions artifacts
├── get-pr-info.py            # Resolve PR numbers from workflow_run events
├── get-baseline-run.py       # Find a successful baseline workflow run
├── post-pr-comment.py        # Post/update PR performance comments
└── requirements.txt
```

Runtime kube-burner metrics are written separately under `e2e/perf-data/metrics/` (not mixed with these scripts).

## CI flow

1. [`e2e-kind`](../../.github/workflows/kind-e2e.yml) runs Multus node-density-cni on thick Multus for every CNI version in the matrix and uploads artifacts named `node-density-cni-<cniVersion>-performance-test-data-<run-id>` containing `metrics/podLatencyMeasurement-node-density-cni-<cniVersion>.json`.
2. [`performance-report`](../../.github/workflows/performance-report.yml) triggers on `workflow_run` completion of `e2e-kind`, generates the Pod Ready Latency report (one section per CNI version), optionally compares against the latest successful `push` baseline, and posts a GitHub PR comment (`🤖 Generated by performance-report workflow`).

## Local report generation

```bash
export GITHUB_TOKEN=$(gh auth token)
python3 -m pip install -r e2e/perf/requirements.txt
python3 e2e/perf/generate_perf_report.py \
  --workload node-density-cni-0.4.0 \
  --metrics-dir e2e/perf-data/metrics \
  --json-output /tmp/performance_data.json \
  --output /tmp/performance_report.md
```
